## 1. Verified Plan Limits, Risks & Fallbacks Register (`[COST-1]`)

| Risk ID | Item & Provider (Confirmed Default: Free / Lowest Tier) | Finding (Verified from Official Docs) | Source Citation | Impact on Azaroth CMS Architecture | Mitigation / Fallback Implemented in Design | Gate 2 Decision Needed? |
|---|---|---|---|---|---|---|
| `RISK-01` | **Vercel Function Payload Size Limit** (Hobby & Pro) | Vercel enforces a hard **4.5 MB** maximum request/response body size for Serverless and Edge Functions on **both** Hobby and Pro plans. | Vercel Docs: *Limits — Serverless Function Payload Size Limit (`4.5 MB`)* (`vercel.com/docs/limits`) | `MED-5a` allows up to **5 MB** for images (and **50 MB** for videos at P1 `MED-5b`). Uploading files through a Vercel API route would fail with `413 FUNCTION_PAYLOAD_TOO_LARGE` for 4.5–5 MB images and all videos. | **Solved in `MED-8`:** Browser uploads directly to `R2_PRIVATE_BUCKET` (`staging/{versionId}/upload.bin`) via short-lived presigned `PUT` URL. The Class B `upload-complete` function reads from R2 server-to-server (`HeadObject` + stream). | No (handled by `MED-8` design). |
| `RISK-02` | **Vercel Hobby Cron Frequency Limit** | Vercel Hobby plan allows at most **2 cron jobs**, each limited to running **once per day** (and with a 1-hour scheduling window). Per-minute/hourly crons require Vercel Pro ($20/mo). | Vercel Docs: *Cron Jobs — Usage & Pricing* (`vercel.com/docs/cron-jobs/usage-and-pricing`) | `MED-9` (`RECON-CORE`) bounds stranded `M2` exposure to `scheduler interval + 1 hour`. If run only once/day via Vercel Hobby Cron, the worst-case bound is `25 hours` instead of `2 hours`. | **Dual-Trigger Design:** We configure `vercel.json` cron once daily (`0 3 * * *`) **and** provide `.github/workflows/backup-and-reconcile.yml` running hourly (`0 * * * *`) against `/api/internal/reconcile` (giving a **2-hour** bound at $0 cost), plus a manual **"Run Reconciliation Now"** button on System Status. | **Yes (Confirm at Gate 2):** Confirm using GitHub Actions hourly cron + Vercel daily fallback on Hobby. |
| `RISK-03` | **Vercel Hobby Non-Commercial Use Restriction** | Vercel's Fair Use Policy and Terms of Service strictly restrict the **Hobby (Free) tier to personal, non-commercial use**. Commercial corporate websites require **Vercel Pro ($20/user/month)**. | Vercel Docs: *Fair Use Guidelines — Commercial Usage* (`vercel.com/docs/limits/fair-use-guidelines`) | Because Azaroth Tech-Hive is a commercial enterprise technology company, hosting its production corporate site on Vercel Hobby violates Vercel's commercial terms. | Staging/preview can run on Hobby during development, but production go-live should either upgrade to **Vercel Pro ($20/mo)** OR activate the **P2 Cloudflare Workers/Pages adapter** (Cloudflare Free & $5/mo Workers Paid permit commercial use). | **⚠️ GATE 2 BLOCKER / DECISION:** Acknowledge Vercel Hobby commercial restriction (plan to use Vercel Pro $20/mo for commercial go-live, or accept risk for staging/preview). |
| `RISK-04` | **Neon Free Tier Compute Budget (`100 CU-hours/month`) vs. Readiness Polling** | Neon Free Tier includes **100 CU-hours/month** per project (`0.25 CU` minimum compute size = 400 active hours/month) and scales to zero after **5 minutes** of inactivity. | Neon Docs: *Plans & Billing — Free Plan* (`neon.tech/docs/introduction/plans`) | Polling `GET /api/health/ready` (which runs `SELECT 1`) every 5 minutes prevents scale-to-zero and consumes **182.5 CU-hours/month**, exhausting the free tier around day 16 of each month. | **Solved in `OBS-2` & `SEO-2`:**<br>1. Public pages and `/api/public/*` are edge-cached (`s-maxage=3600, stale-while-revalidate=86400`), waking Neon only on cache misses and CMS edits.<br>2. External uptime monitors hit `/api/health` (no DB query) every 5 min and `/api/health/ready` at most every **6 hours** (~2.5 CU-hrs/month). | No (mitigated by cache + health split). |
| `RISK-05` | **Neon Free Tier PITR Window (`6 hours` / `1 GB` WAL cap)** | Neon Free Tier retains Point-in-Time Restore (PITR) history for **6 hours**, capped at **1 GB of WAL changes** (Launch plan $19+/mo provides 7 days). | Neon Docs: *Instant Restore (Time Travel) & Plans* (`neon.tech/docs/introduction/plans`) | `BAK-1` requires RPO claims not to exceed the verified PITR window. Any corruption discovered $>6$ hours later cannot use Neon PITR on the Free Tier. | **Solved in `BAK-2`:** Scheduled encrypted `pg_dump` runs every **6 hours** via GitHub Actions to `BACKUP_R2_BUCKET` (providing 90-day retention independent of Neon's 6-hour PITR window). | **Yes (Confirm at Gate 2):** Confirm proposed 6-hour RPO (or upgrade to Neon Launch plan if multi-day PITR is required). |
| `RISK-06` | **Cloudflare R2 Lack of Native S3 Object Versioning** | Cloudflare R2's S3-compatible API supports `CopyObject`, `HeadObject`, and presigned `PUT`/`GET`, but **does not support native S3 Bucket Versioning (`PutBucketVersioning`)**. | Cloudflare R2 Docs: *S3 API Compatibility* (`developers.cloudflare.com/r2/api/s3/api/`) | Cannot rely on S3 native version IDs to recover overwritten objects in place. | **Solved in `MED-1`, `MED-6` & `BAK-3`:** Application keys are immutable (`versions/{versionId}/...` with `If-None-Match: "*"`), and `BAK-3` syncs `versions/` every 6 hours to a separate `BACKUP_R2_BUCKET` under separate credentials without deletes. | No (mitigated by immutable keys + `BAK-3`). |
| `RISK-07` | **Cloudflare R2 Custom Domain Requires a Cloudflare DNS Zone** | Serving `R2_PUBLIC_BUCKET` on a production custom domain with Cloudflare CDN caching requires the domain (or subdomain zone) to be managed on Cloudflare DNS. The `*.r2.dev` managed subdomain is rate-limited and intended for development/testing only. | Cloudflare R2 Docs: *Public Buckets — Custom Domains vs `r2.dev`* (`developers.cloudflare.com/r2/buckets/public-buckets/`) | Without a Cloudflare zone for the media domain, `R2_PUBLIC_BASE_URL` would have to use `*.r2.dev` (rate-limited, no custom edge rules) or proxy through Vercel (consuming Vercel bandwidth). | Use `*.r2.dev` only during pre-domain staging/testing; attach a Cloudflare custom domain (`media.<production-domain>`) before R1 public cutover. | **⚠️ GATE 2 DECISION:** Confirm whether the production domain will use Cloudflare DNS so `media.<domain>` can be attached to `R2_PUBLIC_BUCKET` (and `*.r2.dev` used during staging). |
| `RISK-08` | **Cloudflare R2 Free Tier Operations & Storage Limits** | R2 Free Tier includes **10 GB-month storage**, **1,000,000 Class A ops/month** (`PutObject`, `CopyObject`, `ListObjects`), **10,000,000 Class B ops/month** (`GetObject`, `HeadObject`), and **zero egress fees**. | Cloudflare R2 Docs: *Pricing* (`developers.cloudflare.com/r2/pricing/`) | Site launch media is `< 25 MB` across ~30 assets (with variants `< 100 MB`). Even with 6-hourly `BAK-2`/`BAK-3` jobs (~120 runs/month), storage is `< 0.5 GB` and Class A/B ops are `< 1%` of the free tier. | Keep `ListObjectsV2` bounded and rely on DB state (`RECON-CORE` queries Neon first rather than scanning buckets). | No ($0/mo well within free tier). |
