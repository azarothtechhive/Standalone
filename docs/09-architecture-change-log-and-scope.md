### 2.2 Proposed P0 $\rightarrow$ P1 Cut List (For User Approval at Gate 2 if P0 Needs Streamlining)

We can deliver the **entire P0 scope above** cleanly across Phases 3–7. However, per Section 19 (*"and a P0 size estimate by phase with a proposed cut list — what moves to P1 if P0 is too heavy, for my approval"*), if you want a leaner Phase 4 / faster R1 critical path while keeping **all 10 Critical Invariants (Section 20)** 100% intact, we propose the following **4 candidate cuts** that could move from P0 (R1) to P1 (R2) **only if you approve them at Gate 2**:

| Cut Candidate ID | P0 Item | What Stays in P0 (Preserving Section 20 Critical Invariants) | What Moves to P1 (R2) if Approved | Effort Saved in Phase 4 |
|---|---|---|---|---|
| **`CUT-01`** | **Batch-Publish UI in Media Library on Shared Asset Replacement (`MED-1` sub-feature)** | Immutable versions, atomic replacement across all draft usages, "Used In" reference list (`MED-3`), and aspect-ratio warning (`MED-2a`) stay in P0; Admin can publish from the main Publish bar. | The dedicated multi-page checkbox selector & **"Batch Publish Selected Pages"** modal inside the Media Library moves to P1. | ~250 LOC (Admin UI + batch scope selector) |
| **`CUT-02`** | **Server-Side Responsive Image Variant Resizing in Class B Upload Processor (`MED-5a` / `MED-8` sub-feature)** | Magic-byte type verification, full image decode validation (`sharp`), SVG sanitization (`SEC-4`), SHA-256 checksum, aspect-ratio check, and immutable private/public storage stay 100% in P0. | Generating multiple resized width variants (`sm` 640w, `md` 1024w, `lg` 1600w + `.webp` transcode) for every upload moves to P1 (P0 stores and promotes the verified, stripped original image). | ~300 LOC (Variant matrix + `<picture srcset>` wiring) |
| **`CUT-03`** | **Editor Self-Service Password-Reset Email Flow (`Section 7` / `AUTH-1a` sub-feature)** | Email/password login, mandatory TOTP MFA + recovery codes (`AUTH-1a`), session revocation, login rate limiting, and Admin-initiated user password reset in `/admin/users` stay 100% in P0. | Automated self-service *"Forgot Password"* email dispatch via Resend for the 1–5 internal CMS users moves to P1 (alongside `OBS-4` Resend email alerts). | ~200 LOC (Resend email templates + reset request UI) |
| **`CUT-04`** | **Admin UI for Changing Slot Informative/Decorative Classification (`ALT-4` sub-feature)** | Every slot is seeded with its verified Phase 1 `informative` vs `decorative` classification (`ALT-1`), informative slots require non-empty alt text and block publish if empty (`ALT-2`), and decorative slots render `alt=""` with no alt input (`ALT-3`). | The Admin-only modal to reclassify a slot from `informative` to `decorative` (or vice versa) in the UI moves to P1 (classifications remain locked to the approved Phase 1/2 table at R1). | ~150 LOC (Admin slot reclassification modal + confirmation flow) |

*(Note: Unless you explicitly approve one or more of `CUT-01`..`CUT-04` at Gate 2, we will keep all four in **P0** by default.)*
